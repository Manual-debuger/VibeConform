# Spec 0034: Adopting an Existing Docs Layout

Status: accepted and implemented. Tracks issue #49 ("Adopting an existing
docs layout"). Extends spec 0030 §4 and spec 0033.

## Problem

- A repository that already keeps its ADRs in `docs/adr/`, or its specs
  in `rfcs/`, cannot select `docs_layout: standard` without moving its
  files. The alternative is a docs index and an `AGENTS.md` section that
  point agents at directories that do not exist.
- Guessing the layout from directory names would be unreliable, and
  principle 1 rules it out: fail loudly, do not guess.

## Scope

### 1. Path keys under `development:`

```yaml
development:
  docs_layout: standard
  decisions_dir: docs/adr      # instead of docs/decisions
  specs_dir: rfcs              # instead of docs/specs
```

- There is one optional key per directory: `specs_dir`,
  `architecture_dir`, `decisions_dir`, `development_dir` and
  `operations_dir`. An absent key keeps the default (`docs/specs`,
  `docs/architecture`, `docs/decisions`, `docs/development`,
  `docs/operations`).
- **Explicit only.** Nothing is detected, created or moved.
- Each value is a clean, slash-separated path relative to the
  repository root, by the same rules as a component's `path` (spec 0025).
- `vibe.yaml` is rejected, with the key named, when:
  - a value is not such a path;
  - two of the effective directories are the same, or one is inside
    another;
  - any path key is set without `docs_layout`;
  - `development_dir` is set without `docs_development: on`, or
    `operations_dir` without `docs_operations: on`.
- **An adopted directory must exist.** `diff`, `audit` and `sync` stop
  with an error naming the key when a set path is not a directory in the
  repository. Defaults are not checked: as in spec 0030, they appear
  with the project's first document.

### 2. What the paths change

- The `AGENTS.md` section's knowledge rule names each directory, and
  "write it to `<specs>/` first" names the spec directory.
- The `docs/README.md` layout list links each directory relative to
  `docs/`. A directory outside `docs/` is linked with `../`.
- The specs README section goes in `<specs_dir>/README.md`.
- The docs index stays at `docs/README.md`.

### 3. Moving a directory

Changing `specs_dir` moves the specs section: it is written to the new
directory's README, and the copy recorded at the old path is removed by
the existing removal rules (spec 0029 §5):
- unchanged since sync: removed, with the file if VibeConform created it
  and nothing else is in it;
- modified: kept, as a conflict;
- already gone: forgotten.

The other paths only change text inside sections that do not move.

## Explicit non-goals

- Migrating or renaming files.
- Detecting common layouts.
- Moving the docs index.
- Paths outside the repository.

## Acceptance criteria

- [ ] A path that is invalid, escaping or overlapping, or set without its prerequisite key, is a manifest error naming the key.
- [ ] An adopted directory that does not exist is an error naming the key, and nothing is written.
- [ ] Golden tests cover the overridden `AGENTS.md` section and docs index, including a directory outside `docs/` (linked with `../`).
- [ ] Moving `specs_dir` removes the old unchanged specs section and writes the new one, and keeps a modified old one as a conflict.
- [ ] Without path keys, every generated byte is identical to spec 0033's.
