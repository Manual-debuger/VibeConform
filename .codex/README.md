# .codex/ configuration

Both files are generated by `codex-config`; change their templates under
`internal/module/agents/codex/templates/`, not these copies.

- `config.toml`: project-level Codex settings (approval policy, sandbox
  mode). Codex loads it only when this project directory is trusted.
- `hooks.json`: **no hooks.** VibeConform's Codex hooks are suspended by
  `docs/specs/0024-claude-first-agent-modules.md`; the reasons and what
  resuming would take are in
  `docs/decisions/0011-one-module-per-agent-runtime.md`.

The file stays generated rather than deleted because `vibe sync` never
removes a file a standard stops producing: an empty managed file is what
takes the old hooks out of existing repositories. `config.toml` doesn't
set `hooks = false`, so hooks configured in your own `~/.codex/` still run.

## What the 2026-09-24 canary found

Codex 0.156.1, natively on Windows and in WSL (Ubuntu 24.04), with a
logging hook on every event:

| Behaviour | Linux | Windows |
|---|---|---|
| `SessionStart`, `UserPromptSubmit`, `PreToolUse` (`Bash`, `apply_patch`), `Stop` fire | yes | yes |
| `SessionStart` stdout reaches the model | yes | yes |
| `PreToolUse` exit 2 blocks the command | yes | **no** |
| `Stop` exit 2 continues the turn | yes | **no** |
| Sync `PostToolUse` exit 2 reaches the model | yes | untested |
| Background hook, stderr + exit 2, reaches the model | **no** | untested |
| Background hook, JSON `additionalContext`, reaches the model | yes | untested |

Two earlier beliefs turned out wrong: shell commands on Windows *do* fire
`PreToolUse` in this version (openai/codex#24453 described otherwise), and
file edits fire it too, as `apply_patch` with the patch text in
`tool_input.command`. Paths in that patch were relative on Windows and
absolute on Linux.

On Windows every tool call also failed inside Codex's own sandbox
(`helper_sandbox_lock_failed … SetNamedSecurityInfoW … failed: 5`), so the
`PostToolUse` rows there are untested. The `Stop` result doesn't involve
the sandbox.

## If Codex hooks are resumed

Codex's contract, not Claude Code's, has to drive the design:

- Report from background hooks through JSON `additionalContext`.
- Parse file paths out of `apply_patch` bodies, relative and absolute, for
  the secret-file rules.
- Show on Windows, in a live canary, that exit code 2 or a JSON
  block/deny decision is honoured.
- Codex runs a project hook only after the user trusts its exact
  definition (`/hooks`), and asks again whenever the definition changes.
