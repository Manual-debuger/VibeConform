# .codex/ configuration

Checked against the current OpenAI Codex documentation
(`learn.chatgpt.com/docs/config-file`, `.../docs/hooks`), last on
2026-09-24. Both files are generated by `agent-config`; change their
templates under `internal/module/agents/`, not these copies.

- `config.toml`: project-level Codex settings. Codex loads it only when
  this project directory is trusted.
- `hooks.json`: the same five hooks Claude Code runs, each calling the
  same `task -x hook:<name>` command (`docs/usage.md`, "Agent hooks"):
  - `SessionStart` (`startup|resume|clear`) runs `hook:context`. Codex adds
    its plain stdout as developer context.
  - `PreToolUse` (`Bash`) runs `hook:guard`. That is the same guard, policy
    (`../.claude/hooks/policy.json`), and command Claude Code uses, so the
    destructive-command list exists once. A deny is exit `2` with the
    reason on stderr, which Codex honors. See
    `docs/specs/0021-agent-hooks-task-interface.md`.
  - `PostToolUse` (`apply_patch|Edit|Write`; Codex reports file edits as
    `apply_patch` and accepts the other two as aliases) runs `hook:format`,
    then `hook:check` with `async: true`. Codex runs background hooks
    without waiting, at most eight per session, and delivers their output
    at the next safe point. Claude Code uses `asyncRewake` instead, because
    its plain `async` discards the result.
  - `Stop` runs `hook:done`. On exit 2, Codex continues the turn with the
    reason as its next prompt. `stop_hook_active` tells the hook this
    stop already continued once. Codex documents no cap on repeated
    blocking, which is why `hook:done` lets the second stop through. See
    `docs/specs/0023-agent-lifecycle-hooks.md`.

## Fixed in spec 0021: the file was not in Codex's schema

Until spec 0021, `hooks.json` held a flat entry,
`{"command": …, "commandWindows": …}`, directly under `PreToolUse`. Codex's
documented schema nests handlers: a `matcher`, then a `hooks` array of
`{"type": "command", "command": …}`. The flat shape is not one Codex
describes, so it may never have run the guard at all. A test in
`internal/module/agents` now decodes the file strictly and rejects the flat
shape.

## Known limitations

- **No file-edit hook.** Codex's `PreToolUse` fires for shell commands, not
  for file edits (`apply_patch` and the like). So the secret-file rule that
  guards Claude Code's `Write`/`Edit` calls has **no Codex equivalent**:
  Codex can edit a file like `.env` with no hook intercepting it. Revisit if
  Codex adds a file-edit hook event.
- **No command guard on Windows.** On Windows, Codex runs shell commands as
  `command_execution` events that do not emit `PreToolUse` at all
  ([openai/codex#24453](https://github.com/openai/codex/issues/24453), open
  as of 2026-09-23). No hook configuration can fix that from here.
- **Unconfirmed in a real Codex session** (spec 0023's canaries):
  - whether a failing async `hook:check`'s exit-2 stderr counts as the
    "informational output" Codex delivers;
  - whether `PostToolUse` fires for `apply_patch` in the Codex version you
    run. The documentation says it does, while the `PreToolUse` gap above
    says Codex's edit events have been patchy.

  If the check's output doesn't arrive, the Stop gate still runs.
